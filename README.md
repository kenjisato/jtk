# jtk

jtk（十徳キット）は、授業・研究・学内事務で繰り返す操作を、コマンド 1 本にまとめる個人用の道具箱です。手作業をなくすことと、他の道具に埋もれていたスクリプトを、読んで試せるコードとして手元に置くことがねらいです。

いまあるコマンドは、MS Forms の回答ファイルから、個人を特定できる情報（PII）を除いたコピーを作るものです。そのコピーを AI に渡して分析します。原本は教員と TA が採点に使います。

## インストール

```
uv tool install git+https://github.com/kenjisato/jtk
```

## `jtk table pii drop`

PII の列を消したコピーを作ります。鍵は使いません。1 回分の回答を分析するだけなら、こちらで足ります。

```
jtk table pii drop INPUT --out OUT [--config FILE] [--preset msforms]
    [--pii COL ...] [--omit COL ...] [--move-original PATH] [--force]
```

| オプション | 内容 |
|---|---|
| `INPUT` | 入力の表（.xlsx / .csv） |
| `--out` | 出力先。拡張子は入力と同じにする |
| `--config` | 設定ファイル（TOML）。下の「設定ファイル」を参照 |
| `--preset msforms` | `Email` / `メール` と `Name` / `名前` の列を `--pii` に加える |
| `--pii COL` | 消す個人情報の列（複数可）。漏れの検査で値を探す |
| `--omit COL` | 個人情報ではないが要らない列（複数可）。漏れの検査では探さない |
| `--move-original PATH` | 書き終えた後に原本をそこへ移す。親フォルダは作る |
| `--force` | 出力先・移し先に既にあるファイルを上書きする |

列名は見出しと完全に一致させます。見つからない列があればエラーです。`--pii` も `--omit` もプリセットも無ければ、何も消さないコピーを作る意味がないのでエラーです。

```
jtk table pii drop "03-2 確率の復習.xlsx" --preset msforms --omit ID --omit 開始時刻 --omit 完了時刻 --out out/03-2.xlsx
```

## `jtk table pii hash`

メールアドレスの列をハッシュ値に置き換え、ほかの PII の列を消します。複数回分の回答を同じ人でつなぎたいときに使います。つなぐ必要がなければ `pii drop` を使ってください。

```
jtk table pii hash INPUT --scope SCOPE --out OUT [--config FILE]
    [--preset msforms] [--hash COL] [--hash-column NAME]
    [--pii COL ...] [--omit COL ...] [--move-original PATH] [--force]
```

`pii drop` のオプションに加えて、次があります。

| オプション | 内容 |
|---|---|
| `--scope` | ハッシュの範囲。必須で、既定値はない。例 `2026後期/経済数学I` |
| `--hash COL` | ハッシュにする列。1 列だけ。`--preset msforms` ではメールの列 |
| `--hash-column NAME` | ハッシュ列の名前。既定は `hash` |

`--preset msforms` では、メールの列が `--hash`、名前の列が `--pii` になります。ハッシュ列は、元の列があった位置に入ります。ハッシュにする列に空のセルがあるとエラーです。

```
jtk table pii hash "03-2 確率の復習.xlsx" --preset msforms --scope "2026後期/経済数学I" --omit ID --out out/03-2.xlsx
```

### 鍵の準備

ハッシュには親鍵が要ります。親鍵は OS の鍵保管庫（Windows の資格情報マネージャー、macOS のキーチェーン）に置き、正本は Bitwarden に手で保存します。鍵が無い PC で `pii hash` を実行すると、何も書き出さずに登録の手順を示して止まります。

| コマンド | 内容 |
|---|---|
| `jtk key new` | 親鍵を作って鍵保管庫に入れ、一度だけ表示する。最初の 1 台で、初回だけ使う。表示された鍵を Bitwarden に保存し、指紋もメモに残す |
| `jtk key set` | Bitwarden の親鍵を入力欄（画面に出ない）で受け取り、この PC の鍵保管庫に入れる。2 台目以降で使う。既にあれば `--force` が要る |
| `jtk key fingerprint` | 親鍵の指紋（8 桁）を表示する |

PC ごとに `jtk key fingerprint` を実行し、Bitwarden のメモの指紋と一致することを確かめてください。鍵が食い違うと、ハッシュ値が黙って食い違います。`jtk key new` と `jtk key set` の出力は鍵を含むので、AI の会話の中では実行しないでください。

## 設定ファイル

同じ授業では、スコープ・出力先・ファイル名の形・消す列が毎回同じです。TOML にまとめて `--config FILE` で渡せます。jtk は設定ファイルを探しに行かず、渡されたものだけを読みます。

```toml
[jtk.table.pii]
preset = "msforms"
scope = "2026後期/経済数学I"        # pii hash だけが読む
hash_column = "hash"                 # pii hash だけが読む
pii = ["学籍番号"]
omit = ["ID", "開始時刻", "完了時刻"]
out_dir = "analysis/forms"
out_name = "{stem}"                  # 拡張子は入力と同じものが付く
stem_pattern = '^(\d+-\d+) .*$'      # 任意。{stem} に入れる前にファイル名を書き換える
stem_replace = '\1'
move_original_dir = "private/forms"
```

- 読むのは `[jtk.table.pii]` の表だけです。ほかの表は無視します
- 使えるキーは、上の 10 個と `hash`（`--hash` に当たる）です。どれも省略できます。知らないキーや型の違う値はエラーです
- 相対パスは、設定ファイルのあるフォルダを起点に解決します。どこから実行しても同じ場所になります
- 出力先は `out_dir / (out_name + 入力の拡張子)` です。`out_name` で使える置き換えは `{stem}`（入力のファイル名から拡張子を除いたもの）だけで、既定は `{stem}` です。ほかの `{...}`、`/` `\`、拡張子を含めるとエラーです
- 原本の移し先は `move_original_dir / 入力のファイル名` です
- `pii drop` は `scope`・`hash`・`hash_column` を読まず、あっても無視します。同じ設定ファイルを両方のコマンドで使えます

### ファイル名の書き換え

`stem_pattern` と `stem_replace` は、`{stem}` に入れる前にファイル名（拡張子を除く）を書き換えます。Python の `re.sub(stem_pattern, stem_replace, stem, count=1)` と同じで、後方参照は `\1` または `\g<1>` です。

- 2 つは組で使います。片方だけならエラーです
- TOML ではシングルクォート（`'...'`）で書くと、`\` を重ねずに済みます
- ファイル名がパターンに一致しなければエラーです。別の授業のファイルを誤って渡したときに気づくためです
- 結果が空、または `/` `\` を含めばエラーです

Forms が付ける `(1-100)` を外す例です。

```toml
stem_pattern = '^(.*?)\(\d+-\d+\)$'
stem_replace = '\1'
```

`03-2 確率の復習(1-100).xlsx` は `03-2 確率の復習.xlsx` の名前になります。`SessionNumber-QuizNumber` だけを残す例は、上の設定ファイルの `'^(\d+-\d+) .*$'` と `'\1'` で、同じファイルが `03-2.xlsx` になります。

### コマンドラインとの優先関係

- `--out`・`--move-original`・`--scope`・`--preset`・`--hash`・`--hash-column` は、コマンドラインの指定が優先します
- `--pii`・`--omit` は、設定ファイルの分に追加します
- `--out` は、設定ファイルに `out_dir` があれば省けます。`--scope` も同じで、設定ファイルに `scope` があれば省けます
- `--force` は設定ファイルに置けません。上書きは毎回その場で決めます

## 個人情報の扱い

授業の回答ファイルには、名前やメールアドレスのような、個人を特定できる情報（PII）が入っています。このツールは、AI に回答を分析させる前に、PII を除いたコピーを作ります。コードも処理の中身もこの README で公開しており、ハッシュ値から元のメールアドレスに戻せないことは、後述の鍵が秘密であることだけに頼っています。

### 消すもの

| 指定 | 内容 |
|---|---|
| `--pii` / プリセット | 名前・メールアドレス・学籍番号など、個人を特定する列。消したうえで、その値が他のセルに残っていないかも検査する |
| `--omit` | 個人情報ではないが要らない列。検査では探さない |
| `--hash` | メールアドレスの列。消して、代わりにハッシュ値を入れる |

紐づけが要らないときは、`pii drop` を使い、ID や回答時刻の列も `--omit` で消してください。これらは、他のデータと突き合わせると個人を絞り込む手がかりになります。

### ハッシュ値

紐づけが要るとき（`pii hash`）は、メールアドレスを次の手順でハッシュ値に変えます。

1. 親鍵（ランダムな 32 バイト）と、授業ごとの「スコープ」（例 `2026後期/経済数学I`）から、スコープ鍵を作る
   - スコープ鍵 = HMAC-SHA256(親鍵, `"jtk:pii-hash:v1:"` + スコープ)。スコープは NFC で正規化し、前後の空白を除く
2. スコープ鍵でメールアドレスを変換する
   - ハッシュ値 = HMAC-SHA256(スコープ鍵, メールアドレス) の 16 進の先頭 16 桁。メールアドレスは NFKC で正規化し、前後の空白を除き、小文字にする

同じスコープなら、いつ・どの PC で実行しても、同じ人は同じハッシュ値になります。スコープが違えば、同じ人でもつながりません。親鍵を知らなければ、ハッシュ値は作れず、名簿と照合してもメールアドレスには戻せません。

親鍵は、この PC の OS の鍵保管庫と、教員の Bitwarden にだけあります。このリポジトリにもファイルにも書きません。`jtk key new` 以外のコマンドは、親鍵を表示しません。

### 漏れの検査

書き出す前に、元から残る列のすべてのセルを検査します。

1. 原本の `--hash` と `--pii` の列にある全行の値が、残る列のどこかに含まれていないか。空白を除き、全角半角と大文字小文字の違いをならして比べる。メールアドレスは `@` より前の部分も探す
2. メールアドレスの形をした文字列が無いか

一つでも見つかれば、何も書き出さずに止まります。画面に出るのは行番号・列名・種別だけで、セルの値は出しません。原本は動かさず、失敗したときに出力ファイルも残しません。検査を飛ばすオプションはありません。

この検査では、次を見つけられません。

- 名字だけの記述、あだ名
- 他人の名前
- 4 文字に満たない値（短い値は無関係な文字列に一致しやすいため、探しません）
- .xlsx の数値や日付のセルの中身（文字列のセルだけを検査します）

自由記述に名前が書かれていないかは、検査に頼りきらないでください。

### 処理後のコピーも個人データです

出力は匿名化されたデータではありません。大学が原本を持っているので、ハッシュ値や残った列から原本と照合でき、個人データのままです。処理後のコピーも、個人情報として管理します。

`--move-original`（設定ファイルでは `move_original_dir`）で、原本を別の場所へ移せます。移すのは出力を書き終えた後で、失敗したときは出力を消し、原本は元の場所に残ります。

まれに、別のドライブへの移動が途中で失敗し、原本を元の場所へ戻すことにも失敗することがあります。その場合、原本は移し先のフォルダにある `.` で始まる `.jtk-tmp` のファイルとして残り、エラーの文面にその場所が出ます。消さずに、元の場所へ戻してください。
