# jtk と最初のコマンド `jtk table pii drop` / `jtk table pii hash` の設計

日付: 2026-11-03

## 意図

jtk（十徳キット）は、業務で繰り返す操作を Python 製の CLI にまとめる個人用の道具箱である。対象は授業・研究・学内事務にまたがる。ねらいは二つある。

1. 手作業の繰り返しをコマンド 1 本にする
2. スキル（instructor-kit・literature など）に埋め込まれてブラックボックスになったスクリプトを、読める・試せるコードとして取り戻す。汎用化できるものは jtk に移し、スキルは jtk を呼ぶだけにする。汎用化できないものはスキルに残す。移す作業は本設計の範囲外で、1 本ずつ別に行う

最初のコマンドは、MS Forms の回答ファイルから個人を特定できる情報（PII）を除いたコピーを作る。そのコピーを AI に渡して分析する。原本（個人情報あり）は教員と TA が採点に使う。用途は二つある。

- **落とすだけ（`pii drop`）**：1 回分の回答を分析する。個人を紐づける必要が無いので、PII の列を消せば足りる。こちらのほうが多い
- **紐づける（`pii hash`）**：複数回分の回答ファイルを同じ人でつなぐ。メールアドレスをハッシュ値に置き換えて残す

どちらの出力も、大学が原本を持つ限り照合できるので、法的には**個人データのまま**である（匿名加工情報ではない）。処理後も個人情報として管理する。授業の回答欄では個人的な経験や思想を書かせず、統計として公表もしないので、直接の識別子を除いて基本的な検査を通せば危険は低い、という判断に立つ。

AI に回答データを渡す以上、**個人情報をどう扱っているかを学生や第三者に開示できること**が要件になる。そのためにコードは public にし、README に処理内容を平易に書く。安全性は鍵が秘密であることだけに依存させ、仕組みは隠さない。

## 目標

- `jtk table pii drop`：表ファイル（.xlsx / .csv）の指定列を消したコピーを保存する。鍵もスコープも要らない
- `jtk table pii hash`：上に加えて、指定した 1 列を鍵付きハッシュに置き換える
- どちらも、原本を指定した場所へ移せる。書き出す前に漏れの検査を行う
- MS Forms の出力（英語版・日本語版の列名）をプリセットで扱える
- 授業ごとに共通の引数（スコープ・出力先のフォルダ・ファイル名の形・消す列）を設定ファイルにまとめ、`--config` で渡せる
- `pii hash` では、同じ「スコープ」（学期 + 授業）なら、いつ・どの PC で実行しても同じ人は同じハッシュ値になる。スコープが違えば同じ人でもつながらない
- 鍵は OS の鍵保管庫に置く。正本は Bitwarden に手で保存する。レポにもファイルにも書かない
- コードに授業名・学生の情報・大学固有の値を含めない。public で公開できる

## 非目標

- スキルからのスクリプト移行（別の設計で 1 本ずつ）
- PyPI への公開。インストールは `uv tool install git+https://github.com/kenjisato/jtk`
- 複数ファイルのマージ。jtk はつなぐための鍵を作るだけで、マージは利用者や AI が行う
- ハッシュ値から人を引き戻すコマンド。原本に同じ処理をかければ対応表は作れる（将来の候補）
- 法的・統計的な意味での匿名化（k-匿名性など）。準識別子（ID・時刻など）を消すかは利用者が `--omit` で選ぶ
- 鍵保管庫の無い環境（GUI の無い Linux サーバなど）での `pii hash`。`pii drop` は鍵を使わないので動く
- MS Forms 以外のプリセット

## してはならないこと（動いても失敗とみなすもの）

- **個人情報の値を端末に出す。** 出力・警告・エラーのどれにも、PII の列や削除対象の列の値を含めない。行番号・列名・種別（「名前」「メール」など）だけを出す。jtk は Claude Code から実行されることがあり、端末出力は AI の文脈に入るからである
- **PC ごとに黙って違う鍵を使う。** 鍵が無い PC で勝手に鍵を作るとハッシュ値が食い違い、マージが黙って壊れる
- **半端な出力を残す。** 失敗したら出力ファイルを作らず、原本も動かさない
- **個人情報が残ったコピーを書き出す。**（下の「漏れの検査」）

## 外から見える振る舞い

### 共通

```
jtk table pii drop INPUT [--config FILE] --out OUT
    [--preset msforms] [--pii COL ...] [--omit COL ...]
    [--move-original PATH] [--force]

jtk table pii hash INPUT [--config FILE] --scope SCOPE --out OUT
    [--preset msforms] [--hash COL] [--pii COL ...] [--omit COL ...]
    [--hash-column NAME] [--move-original PATH] [--force]
```

`--config` を渡せば、`--out` と `--scope` を含め、`--force` 以外の引数を設定ファイルから読める（下の「設定ファイル」）。

- 列の役割は 3 種類ある
  - `--hash COL`（`pii hash` のみ）：ハッシュ値に置き換える列。**1 列だけ**（2 列以上はエラー）。つなぐための鍵を 1 つに定めるため。漏れの検査で探す値の出どころにもなる
  - `--pii COL`：個人情報として消す列。漏れの検査で探す値の出どころになる
  - `--omit COL`：個人情報ではないが要らないので消す列（点数など）。漏れの検査では探さない
- `--preset msforms`：
  - `pii drop`：`--pii` = `Email` または `メール`、および `Name` または `名前`
  - `pii hash`：`--hash` = `Email` または `メール`、`--pii` = `Name` または `名前`
  - どちらの言語の列名でも一致する。`--pii` / `--omit` を併記したら、プリセットに追加する
- 列名は見出しと完全一致で照合する。指定した列が見つからなければエラー
- 出力の形式は入力と同じにする（.xlsx → .xlsx、.csv → .csv）。`--out` の拡張子が入力と違えばエラー。形式をまたぐと日付や数値の文字列化が問題になるので、v1 では扱わない
- CSV はすべてのセルを文字列として読み、そのまま書く（型の推測をしない）。UTF-8（BOM 付き）で書き、Excel でそのまま開けるようにする。入力は BOM の有無どちらでも読む
- .xlsx は最初のシートを読む。シートが複数あれば警告する
- 触らない列の値は変えない（日付は日付のまま、数値は数値のまま）
- `--move-original`：出力を書き終えた後に原本をそこへ移す。親ディレクトリが無ければ作る
- `--out` や `--move-original` の先に既にファイルがあればエラー。`--force` で上書きする
- 終わったら要約を表示する：出力先、行数、削除した列、漏れの検査の結果。`pii hash` では加えて、追加した列、スコープ、鍵の指紋

### 設定ファイル（`--config`）

同じ授業では、スコープ・出力先のフォルダ・ファイル名の形・消す列が毎回同じである。これを TOML の設定ファイルにまとめ、`--config FILE` で渡せるようにする。

```toml
[jtk.table.pii]
preset = "msforms"
scope = "2026後期/経済数学I"        # pii hash だけが読む
hash_column = "hash"                 # pii hash だけが読む
pii = ["学籍番号"]
omit = ["ID", "開始時刻", "完了時刻"]
out_dir = "analysis/forms"
out_name = "{stem}"                  # 拡張子は入力と同じものが付く
stem_pattern = '^(\d+-\d+) .*$'      # 任意。{stem} に入れる前にファイル名を書き換える
stem_replace = '\1'
move_original_dir = "private/forms"
```

この例では、`03-2 確率の復習(1-100).xlsx` の出力が `analysis/forms/03-2.xlsx` になる。

- 読むのは `[jtk.table.pii]` の表だけである。他の表は、jtk の将来のコマンドや他の道具の設定のために空けておき、あっても無視する。jtk 以外の道具と共通の設定ファイルに書けるよう、jtk の表はすべて `jtk.` の下に置く
- キーは上の 10 個と `hash`（`--hash` に当たる）。どれも省略できる。知らないキーがあればエラーにする。綴りを誤った設定が黙って効かないのを防ぐため
- 値の型が違えば（`pii` が文字列の配列でないなど）エラーにする
- 相対パスは、設定ファイルのあるディレクトリを起点に解決する。どこから実行しても同じ場所になるようにするため
- 出力先は `out_dir / (out_name を展開したもの + 入力の拡張子)` とする
  - `out_name` で使える置き換えは `{stem}`（入力のファイル名から拡張子を除いたもの）だけ。既定は `{stem}`
  - それ以外の `{...}`、パスの区切り文字（`/` `\`）、拡張子（`.xlsx` `.csv`）を含めばエラーにする
- `stem_pattern` / `stem_replace`：`{stem}` に入れる前に、ファイル名（拡張子を除く）を正規表現で書き換える
  - Python の `re.sub(stem_pattern, stem_replace, stem, count=1)` と同じ。sed の `s/パターン/置換/` に当たる（`g` なし）。後方参照は `\1` または `\g<1>`
  - TOML ではシングルクォートの文字列（`'...'`）で書くと、`\` を重ねずに済む
  - 2 つは組で使う。片方だけならエラー
  - 照合の前にファイル名を NFC に正規化する。macOS のファイル名は濁点が分かれた形（NFD）で渡ることがあり、そのままでは日本語を含むパターンが一致しないため
  - ファイル名がパターンに一致しなければエラーにする。一致しないまま元の名前で書き出すと、別の授業のファイルを誤って渡したときなどに気づけないため
  - 書き換えた結果が空、またはパスの区切り文字を含めばエラーにする
  - 正規表現として正しくなければ、設定ファイルを読んだ時点でエラーにする
- 原本の移動先は `move_original_dir / 入力のファイル名` とする
- コマンドラインとの関係
  - `--out`・`--move-original`・`--scope`・`--preset`・`--hash`・`--hash-column` は、コマンドラインの指定が優先する
  - `--pii`・`--omit` は、設定ファイルの分に追加する（プリセットの扱いと揃える）
  - `--force` は設定ファイルに置けない。上書きは毎回その場で判断するため
- `--out` は、設定ファイルが `out_dir` を持つなら省ける。どちらも無ければエラー。`--scope` も同じ
- `pii drop` は `scope`・`hash`・`hash_column` を読まず、あっても無視する。同じ設定ファイルを両方のコマンドで使えるようにするため
- 設定ファイルには個人情報を書かない。置き場所は授業ごとの作業フォルダを想定する。jtk は設定ファイルを探しに行かず、`--config` で渡されたものだけを読む
- 設定ファイルを使ったときは、要約にそのパスも出す

### `jtk table pii drop`

- 指定した列を消すだけである。鍵保管庫に触れない
- `--pii` も `--omit` も（プリセットも）無ければエラー。何も消さないコピーを作る意味が無いため

### `jtk table pii hash`

- `--scope`（必須、既定値なし）：例 `2026後期/経済数学I`。既定値を置かないのは、別の授業どうしが誤ってつながるのを防ぐため
- ハッシュ対象の列は元の列としては残らない。ハッシュ列はその列があった位置に入る。列名の既定は `hash`

エラーにする入力：ハッシュ対象の列に空のセルがある（匿名回答のフォームなど）。同じファイル内で異なる値が同じハッシュ値になった（事実上起きないが、検査は安い）。どちらも行番号を示す。

### 漏れの検査

書き出す前に、残る列のすべてのセルを検査する。両方のコマンドで同じ検査を行う。

1. 原本の `--hash` と `--pii` の列に入っている値（その行に限らず全行分）が、部分文字列として現れないか。比較の前に両方の空白を除き、NFKC で正規化し、小文字にする。メールアドレスは `@` より前の部分も探す
2. メールアドレスの形をした文字列が無いか

検査するのは文字列のセルだけである（.xlsx の数値・日付のセルは対象外。CSV はすべて文字列）。探す値が正規化後 4 文字未満なら探さない。短い値は無関係な文字列に一致しやすく、検査を飛ばす手段が無いので、誤検出で道具が使えなくなるのを避けるためである。数字だけの値（学籍番号がアドレスの `@` より前にある場合など）も探す。自由記述に書かれた学籍番号は漏れなので、見逃さないほうを選ぶ。

一つでも見つかれば何も書き出さず、行番号・列名・種別を列挙して終了コード 1 で終わる。自由記述やフィードバックに名前が入っていた場合は、原本を直すか、その列を `--omit` するかを利用者が選ぶ。v1 では検査を飛ばすオプションを置かない（私の判断。個人情報入りのコピーが AI に渡る道を作らないため）。

この検査では、名字だけの記述・あだ名・他人の名前は見つけられない。この限界は README に書く。

### ハッシュ値の作り方

- 親鍵：ランダムな 32 バイト。base64url の文字列として保存する
- スコープ鍵 = HMAC-SHA256(親鍵, `"jtk:pii-hash:v1:" + scope`)。`scope` は NFC で正規化し、前後の空白を除く
- ハッシュ値 = HMAC-SHA256(スコープ鍵, 正規化したメールアドレス) の先頭 16 桁（16 進）。正規化は NFKC、前後の空白除去、小文字化
- 16 桁（64 ビット）にするのは、表で扱いやすい長さにするため。授業の人数なら衝突は事実上起きない

この作り方は README とコードで公開する。親鍵を知らなければスコープ鍵もハッシュ値も作れず、名簿と照合しても元のアドレスには戻せない。`v1` は作り方を変えるときの区切りである。

### `jtk key`

- `jtk key new`：親鍵を作って鍵保管庫に入れ、**一度だけ**表示する。利用者は Bitwarden に保存する。手元に既に鍵があれば拒否する。表示時に「Bitwarden に既にあるなら `jtk key set` を使う」と添える
- `jtk key set`：入力欄（エコーなし）で親鍵を受け取り、形式を検査して鍵保管庫に入れる。既にあれば `--force` を求める
- `jtk key fingerprint`：鍵の指紋（HMAC-SHA256(親鍵, `"jtk:fingerprint"`) の先頭 8 桁）を表示する。Bitwarden のメモに指紋を残しておけば、各 PC の鍵が同じか確かめられる
- 鍵保管庫の操作は `keyring` ライブラリで行う（Windows の資格情報マネージャー、macOS のキーチェーン）。サービス名 `jtk`、ユーザ名 `master`
- 鍵が無い PC で `pii hash` を実行したら、登録手順（Bitwarden からコピーして `jtk key set`）を示して止まる。鍵保管庫が使えない環境でも同様に止まる

`new` 以外のコマンドは親鍵を表示しない。

## 制約

- 実行環境：Windows と macOS。Python は uv で管理し、uv の慣習に従う（`pyproject.toml`、`src/` レイアウト）
- テストには架空のデータだけを使う。実在の名前・アドレス・大学のドメインをレポに入れない
- README は日本語。「個人情報の扱い」の節を設け、学生に見せられる言葉で、次を説明する
  - PII という語の意味（「個人を特定できる情報」と一度言い換えてから使う）
  - 消す列・変換の方法・鍵の置き場所・検査とその限界
  - 処理後のコピーも個人データとして管理すること（匿名化ではない）
  - 紐づけが要らないときは、ID や回答時刻の列も `--omit` で消すよう勧めること

## 私の判断（利用者と合意したものではない）

- CLI は Typer で作る。サブコマンドの階層（`jtk table pii ...`、`jtk key ...`）を作りやすく、Python の CLI として標準的なため
- ライセンスは MIT
- 漏れの検査を飛ばすオプションを置かない
- ハッシュ値の長さは 16 桁
- CSV は BOM 付き UTF-8 で書く
- 消す列を `--pii`（漏れの検査で探す）と `--omit`（探さない）に分ける。点数のような列の値まで探すと、ほとんどのセルに一致して常に失敗するため
- ハッシュ対象は 1 列だけ
- 出力の形式は入力と同じに限る
- 漏れの検査は文字列のセルだけを対象にし、4 文字未満の値は探さない。数字だけの値は探す
- 設定ファイルは TOML（Python 標準の `tomllib` で読める）。`[jtk.table.pii]` の表に置き、他のコマンドが後から自分の表を足せるようにする
- 設定ファイルは `--config` で明示したときだけ読む。カレントディレクトリなどを自動で探さない（どの設定が効いたか分からなくなるため）
- `out_name` の置き換えは `{stem}` だけにする。日付などは要望が出てから足す
- ファイル名の書き換えは `stem_pattern` / `stem_replace` の 1 組だけにする（複数の置換を順にかける形にはしない）。ファイル名がパターンに一致しなければエラーにする

利用者と合意したもの：コマンドを `pii drop` / `pii hash` の 2 本に分ける。処理後のコピーは個人データとして扱う。同じ授業で共通の引数（スコープ・出力先・ファイル名の形など）を設定ファイルから読めるようにする。

## 実装者に任せること

- .xlsx の読み書きのライブラリ（openpyxl を直接使うか pandas を介すか）。ただし「触らない列の値は変えない」を満たすこと
- パッケージ内のファイル分け。ジャンルはサブパッケージ（`jtk.table` など）で分ける
- CI の構成（Windows と Ubuntu で pytest を回す程度で足りる）

## 受け入れ条件

- 英語版・日本語版の Forms 形式の架空ファイルに `pii hash --preset msforms` をかけると、メール・名前の列が消え、`hash` 列が元のメール列の位置に入る。他の列は値も型も変わらない
- 同じファイルに `pii drop --preset msforms` をかけると、メール・名前の列が消え、他の列は値も型も変わらない。鍵が無い状態でも動く
- 同じスコープ・同じ鍵なら、別のファイルでも同じアドレス（大文字・空白違いを含む）が同じハッシュ値になる。スコープを変えると値が変わる
- 自由記述の列に別の行の回答者の名前やメールアドレスを入れた架空ファイルでは、どちらのコマンドでも何も書き出されず、行番号と列名が示される。端末出力に値そのものは出ない
- 鍵が無い状態で `pii hash` を実行すると、何も書き出さずに登録手順を示す
- 設定ファイルに `scope`・`out_dir`・`out_name`・`move_original_dir` を書いて `--config` だけを渡すと、`out_dir` に `out_name` の名前で出力ができ、原本が `move_original_dir` へ移る。相対パスは、どこから実行しても設定ファイルのある場所が起点になる
- `stem_pattern = '^(\d+-\d+) .*$'`、`stem_replace = '\1'` で、`03-2 確率の復習(1-100).xlsx` の出力が `03-2.xlsx` になる。ファイル名が NFD でも同じ結果になる。一致しないファイル名では何も書き出さない
- 設定ファイルに知らないキーがあると、何も書き出さずにそのキー名を示す
- 失敗したどの場合でも、出力ファイルは作られず、原本は元の場所に残る
- 上のそれぞれに自動テストがある
