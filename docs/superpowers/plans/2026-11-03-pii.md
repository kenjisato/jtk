# jtk と `jtk table pii drop` / `jtk table pii hash` 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 表ファイル（.xlsx / .csv）から個人を特定できる列を消したコピーを作る CLI `jtk` を、空のレポから作る。`pii drop` は消すだけ、`pii hash` は 1 列を鍵付きハッシュに置き換えて回をまたいで紐づける。

**Architecture:** uv の `src/` レイアウトの Python パッケージ。暗号（`jtk.crypto`）と鍵保管庫（`jtk.keys`）は純粋な関数とし、表の読み書き（`jtk.table.io`）・列の変換（`jtk.table.pii`）・漏れの検査（`jtk.table.leaks`）を分ける。2 つのコマンドは同じ処理の流れを共有し、違いは「ハッシュ列を作るか」と「鍵を読むか」だけにする。CLI（Typer）は各モジュールを順に呼ぶだけの薄い層にする。

**Tech Stack:** Python ≥ 3.11、uv（ビルドは `uv_build`）、Typer、openpyxl、keyring、pytest。

**Spec:** [docs/superpowers/specs/2026-11-03-pii-design.md](../specs/2026-11-03-pii-design.md)

## Global Constraints

- **個人情報の値を端末に出さない。** 出力・警告・エラーには行番号・列名・種別だけを出す。すべての `typer.Typer(...)` に `pretty_exceptions_enable=False` を付ける（Typer の既定のトレースバックはローカル変数＝セルの値を表示するため）
- 失敗したら出力ファイルを作らず、原本も動かさない。jtk の失敗はすべて終了コード 1
- `pii drop` は鍵保管庫に触れない（`keys` を呼ばない）
- 鍵保管庫：`keyring`、サービス名 `jtk`、ユーザ名 `master`。`jtk key new` 以外は親鍵を表示しない
- ハッシュの作り方（そのまま実装する）：
  - スコープ鍵 = HMAC-SHA256(親鍵, `"jtk:pii-hash:v1:" + NFC(scope).strip()`)
  - ハッシュ値 = HMAC-SHA256(スコープ鍵, NFKC(email).strip().lower()) の 16 進の先頭 16 桁
  - 指紋 = HMAC-SHA256(親鍵, `"jtk:fingerprint"`) の 16 進の先頭 8 桁
  - 親鍵 = ランダムな 32 バイト。base64url、パディング `=` なしで保存・表示する。読むときはパディングの有無どちらも受け、32 バイトでなければ拒否
- テストには架空のデータだけを使う。アドレスは `example.com` / `example.jp` / `example.org` のみ。実在の大学のドメインや授業名をコードに入れない（`--scope` の例示は除く）
- メッセージ・README は日本語
- ライセンス MIT。著作者 `Kenji Sato`
- テストは `uv run pytest` で流す。鍵保管庫を使うテストはすべて、メモリ上の偽の keyring バックエンド（Task 2 の `fake_keyring` フィクスチャ）を使い、実機の資格情報マネージャーに触れない

## Review Focus

1. **Typer / Python のトレースバックによる値の漏出。** 想定外の例外（壊れた .xlsx、読めない CSV）でも、端末にセルの値が出ない → Task 2 と Task 7 で `pretty_exceptions_enable=False` を検査し、Task 7 で壊れた入力の出力に値が無いことを検査する
2. **見かけ上の空行。** .xlsx は書式だけの空行を `max_row` に含め、CSV は末尾に空行を持つことがある。全セルが空の行は読み飛ばす（ハッシュ列が空というエラーにしない）→ Task 3
3. **見出しの重複・欠け。** 役割を与えた列名が見出しに 2 回現れたらエラー。見出しが空のセルは `""` として扱う → Task 4
4. **Excel で開いたままの原本（Windows）。** 原本の移動が失敗したら、書いた出力を消してエラーにする → Task 7
5. **全角の空白・全角の英字・全角の `＠` を含む名前やアドレス。** 漏れの検査は NFKC 後に照合するので、全角で書かれた名前・アドレスも見つける → Task 5

### Task 3: 表の読み書き

**Files:**
- Create: `src/jtk/table/__init__.py`, `src/jtk/table/io.py`

**Interfaces:**
- Produces:
  - `@dataclass class Table: headers: list[str]; rows: list[list[object]]; row_numbers: list[int]; sheet_title: str | None = None` — `row_numbers[i]` は `rows[i]` の表計算ソフトの行番号
  - `io.read_table(path: Path) -> tuple[Table, list[str]]` — 2 つ目は警告（値を含まない文字列）
  - `io.write_table(table: Table, path: Path) -> None` — 形式は `path` の拡張子で決める
  - `io.SUPPORTED_SUFFIXES = (".xlsx", ".csv")`。拡張子は大文字小文字を区別せず判定。それ以外は `JtkError`

振る舞い：
- CSV：`encoding="utf-8-sig"`, `newline=""` で読み書き。すべて `str`。見出しより短い行は `""` で埋め、長い行は `JtkError`（行番号のみ）。書くときも `utf-8-sig`

- 全セルが空（`None` または空白だけの文字列）の行は読み飛ばす。`row_numbers` は飛ばした分を詰めない
- 壊れたファイル・読めないファイルは `JtkError("<ファイル名> を表として読めません")`（例外の本文を連結しない。openpyxl や csv の例外メッセージにセルの値が入ることがあるため）

### Task 4: 列の役割の解決と変換

**Files:**
- Create: `src/jtk/table/pii.py`
- Test: `tests/test_pii.py`

**Interfaces:**
- Consumes: `Table`（Task 3）、`crypto.hash_email`（Task 1）
- Produces:
  - `Mode = Literal["drop", "hash"]`
  - `@dataclass class Roles: hash: str | None; pii: list[str]; omit: list[str]` — `drop` モードでは `hash` は常に `None`
  - `PRESETS = {"msforms": {"email": ["Email", "メール"], "name": ["Name", "名前"]}}`
  - `resolve_roles(headers: list[str], *, mode: Mode, preset: str | None, hash_cols: list[str], pii: list[str], omit: list[str]) -> Roles`
  - `transform(table: Table, roles: Roles, *, scope_key: bytes | None, hash_column: str = "hash") -> Table` — 元の表は変えない。返す表の `row_numbers` と `sheet_title` は元のまま。`roles.hash` があるのに `scope_key` が `None` なら `ValueError`（プログラムの誤り）

`resolve_roles` の規則（どれも違反は `JtkError`、メッセージには列名だけ）：
- プリセットの各項目（`email`, `name`）は、候補のうち見出しにある列を使う。候補が 1 つも無ければ「プリセット msforms の列（Email / メール）が見つかりません」。2 つともあればエラー
- `hash` モード + プリセット：`email` → `hash`、`name` → `pii`。`drop` モード + プリセット：`email` と `name` の両方 → `pii`（この順）
- `hash` モード：プリセットと `--hash` の併用はエラー。どちらも無ければエラー。`--hash` が 2 つ以上ならエラー
- `drop` モード：`hash_cols` は空のはず（CLI に引数が無い）。最終的に `pii` も `omit` も空ならエラー「消す列が指定されていません」
- `--pii` / `--omit` はプリセットの後に追加する
- 指定した列が見出しに無ければエラー。見出しに 2 回以上ある列に役割を与えたらエラー
- 同じ列が 2 つの役割に入ったらエラー（同じ役割の重複指定は 1 つにまとめてよい）

`transform` の規則：
- `pii` と `omit` の列を消す。他の列は順序も値もそのまま
- `roles.hash` があれば、その列の位置にハッシュ列（名前 `hash_column`）を入れる
  - `hash_column` が残る列の名前と同じならエラー
  - ハッシュ対象のセルが空（`None` か空白だけ）の行があればエラー。全部の行番号を示す：「ハッシュ対象の列 Email に空のセルがあります（行 3, 7）」
  - 正規化後に異なるアドレスが同じハッシュ値になったらエラー（両方の行番号）。同じアドレスが何行あってもよい
  - セルが文字列でなければ `str()` してからハッシュする

### Task 5: 漏れの検査

**Files:**
- Create: `src/jtk/table/leaks.py`
- Test: `tests/test_leaks.py`

**Interfaces:**
- Consumes: `Table`, `Roles`
- Produces:

  - `collect_needles(original: Table, roles: Roles) -> dict[str, str]` — `roles.hash`（あれば）と `roles.pii` の列の全セルから作る。正規化した探す値 → 種別。種別は `"<列名> の値"`、`@` を含む値については `@` より前も `"<列名> の @ より前"` として入れる。正規化後 4 文字未満の値は入れない。数字だけの値も入れる。セルが文字列でなければ `str()` してから

**Files:**

**Interfaces:**
- Consumes: Task 1–6 のすべて
- Produces: `table.cli.app: typer.Typer`。その下に `pii` の Typer（`app.add_typer(pii_app, name="pii")`）、コマンド `drop` と `hash`。どの Typer も `pretty_exceptions_enable=False`

引数は設計書のとおり：
- 共通：`INPUT`, `--config`, `--out`, `--preset`, `--pii`（複数可）, `--omit`（複数可）, `--move-original`, `--force`
- `hash` のみ：`--scope`, `--hash`（複数可、2 つ以上は Task 4 がエラーにする）, `--hash-column`
- Typer の上では `--out` も `--scope` も省略可能にし、設定ファイルと合わせた後に無ければ `JtkError`（「--out か、設定ファイルの out_dir が要ります」「--scope か、設定ファイルの scope が要ります」）

設定ファイルとの合わせ方（`--config` が無ければ `PiiSettings()` と同じ扱い）：
- `out` = `--out` があればそれ、無ければ `output_path(settings, INPUT)`
- `move_original` = `--move-original` があればそれ、無ければ `moved_original_path(settings, INPUT)`
- `scope` / `preset` / `hash` / `hash_column`（既定 `"hash"`）= コマンドライン優先。`hash` は `--hash` が 1 つでもあれば設定ファイルの分を使わない
- `pii` / `omit` = 設定ファイルの分 + コマンドラインの分
- `drop` コマンドは `settings.scope` / `hash` / `hash_column` を読まない

2 つのコマンドは 1 つの内部関数を呼ぶ。処理の順（どこで失敗しても、それまでに何も書いていないこと）：
0. `--config` があれば `load_pii_settings`、上のとおり合わせる
1. 経路の検査：INPUT が存在する。`--out` の拡張子（大文字小文字無視）が INPUT と同じ。`--out` と `--move-original` が INPUT と同じ経路でない、互いに同じでない（`Path.resolve()` で比較）。`--out` / `--move-original` の先にファイルがあり `--force` が無ければエラー
2. `hash` のみ：`keys.load_master_key()`、`derive_scope_key`。`drop` は `keys` を呼ばない
3. `read_table`。警告は stderr へ
4. `resolve_roles(mode=…)` → `transform`
5. `collect_needles(元の表)` → `find_leaks`。見つかれば「個人情報が残っています。何も書き出していません。」の後に 1 件 1 行 `行 3 / 列 Q1 / Name の値` を並べ、原本を直すか `--omit` するよう促して終了コード 1
6. 書き出し：`--out` と同じディレクトリの一時ファイル（`.` で始まり、同じ拡張子）に `write_table` し、`os.replace` で `--out` へ。親ディレクトリが無ければ作る。失敗したら一時ファイルを消す
7. `--move-original`：親ディレクトリを作り、`shutil.move`。失敗したら（Excel で開いたままなど）書いた `--out` を消し、「原本を移せませんでした（Excel などで開いていないか確かめてください）。出力は消しました。」で終了コード 1
8. 要約を stdout へ：出力先、行数、削除した列、`漏れの検査: 見つかりませんでした`、原本を移したならその先、設定ファイルを使ったならそのパス。`hash` では加えて、追加した列、スコープ、鍵の指紋

  - 設定ファイル：設計書の例、使えるキー、相対パスの起点、`out_name` の `{stem}`、`stem_pattern` / `stem_replace`（Forms の `(1-100)` を外す例と `SessionNumber-QuizNumber` だけを残す例。TOML ではシングルクォートで書くこと）、コマンドラインとの優先関係、`--force` は置けないこと
  - **個人情報の扱い**（学生に見せられる言葉で）：
    - 「個人を特定できる情報（PII）」と一度言い換えてから PII の語を使う
    - 消す列（`--pii` / `--omit` / プリセット）
    - `pii hash` でメールアドレスをハッシュ値に変える方法（Global Constraints の式をそのまま。親鍵を知らなければ戻せないこと、スコープが違えばつながらないこと）と鍵の置き場所（OS の鍵保管庫と Bitwarden。レポにもファイルにも無い）
    - 漏れの検査の内容と**限界**（名字だけ・あだ名・他人の名前・4 文字未満の値・数値や日付のセルは見つけられない）。端末に値を出さないこと
    - 処理後のコピーも個人データとして管理すること（匿名化ではない。原本と照合できるため）
    - 紐づけが要らないときは、ID や回答時刻の列も `--omit` で消すよう勧めること
